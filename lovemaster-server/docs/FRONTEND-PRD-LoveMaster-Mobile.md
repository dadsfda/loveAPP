## 1. 项目目标

LoveMaster 移动端前端用于承接当前后端已实现的情侣关系管理能力，让用户可以在手机上完成注册登录、情侣配对、纪念日管理、喜好记录、约会灵感查看、回忆记录和 AI 沟通建议。

本阶段优先做移动端 H5，而不是直接做 iOS / Android 原生 App。H5 可以先在手机浏览器中验证产品体验，后续再封装为 App 或迁移到跨端框架。

## 2. 用户与使用场景

目标用户是稳定交往中的情侣，主要在手机上使用。典型场景包括：

1. 新用户注册登录后，查看自己的配对邀请码。
2. 一方输入另一方邀请码完成情侣配对。
3. 查看恋爱天数和即将到来的纪念日。
4. 记录 TA 的喜好、雷区和礼物偏好。
5. 浏览约会灵感，快速找到可执行活动。
6. 上传图片并记录专属回忆。
7. 争吵或表达困难时，用 AI 生成更温和的话术。

## 3. 前端产品原则

1. 移动端优先：所有页面按手机尺寸设计，桌面端只作为预览容器。
2. 真实接口优先：后端已有接口必须尽量接入，不把已实现能力做成纯静态假页面。
3. 隐私清晰：个人可见和双方可见必须在创建入口明确展示。
4. 情绪克制：视觉温暖，但不幼稚；文案友好，但不替用户做关系判断。
5. 分阶段交付：先跑通登录、首页、配对、回忆、AI，再逐步补完整 CRUD。

## 6. MVP 页面范围

### 6.1 登录 / 注册

目标：让用户进入系统并拿到 token。

功能：

- 用户名输入。
- 密码输入。
- 登录按钮。
- 注册入口。
- 登录失败错误提示。
- 登录成功保存 `accessToken` 和 `refreshToken`。

接口：

- `POST /api/v1/auth/login`
- `POST /api/v1/auth/register`

验收：

- 能注册新用户。
- 能登录并进入首页。
- 刷新页面后仍保持登录态。
- 401 时跳回登录页。

### 6.2 首页 / 纪念日

目标：作为用户打开 App 后的主页面，展示关系状态和即将到来的日子。

功能：

- 展示“我们在一起 N 天”。
- 展示即将到来的纪念日列表。
- 支持空状态：还没有纪念日。
- 支持新增纪念日入口。
- 默认以展示为主，点击右上角加号或“记录一个重要日子”后展开新增表单。
- 提供快捷入口：喜好、回忆、沟通、配对/关系。

接口：

- `GET /api/v1/users/me`
- `GET /api/v1/pairings/me`
- `GET /api/v1/anniversaries`
- `POST /api/v1/anniversaries`

验收：

- 已登录用户可看到自己的信息和纪念日。
- 未配对用户看到配对引导。
- 纪念日列表来自真实接口。

### 6.3 配对 / 我们的关系

目标：完成情侣关系绑定。

功能：

- 展示我的邀请码。
- 输入对方邀请码。
- 完成配对。
- 查看当前配对状态。
- 可选：解除配对入口，MVP 可先隐藏。

接口：

- `GET /api/v1/pairings/me`
- `POST /api/v1/pairings/bind`
- `POST /api/v1/pairings/unbind`

验收：

- 未配对时显示邀请码和输入框。
- 配对成功后显示伴侣昵称和配对时间。
- 自己的邀请码不能用于配对。

### 6.4 喜好档案

目标：记录自己或伴侣的偏好、雷区、礼物线索。

功能：

- 喜好列表。
- 按分类展示：饮食、礼物、约会、雷区、自定义。
- 新增喜好。
- 可见性选择：仅自己 / 双方。
- 标签输入。
- 默认以展示为主，点击右上角加号或“记录一条新的偏好”后展开新增表单。
- 前端显示中文分类，提交后端枚举值：
  - 礼物：`GIFT`
  - 饮食：`FAVORITE_FOOD`
  - 约会：`HOBBY`
  - 雷区：`LIFE_BOUNDARY`
  - 自定义：`CUSTOM`

接口：

- `GET /api/v1/preferences`
- `POST /api/v1/preferences`
- `PUT /api/v1/preferences/{id}`
- `DELETE /api/v1/preferences/{id}`

验收：

- 能展示喜好列表。
- 能新增个人可见喜好。
- 未配对用户创建双方可见喜好时展示后端错误。

### 6.5 约会灵感

目标：让用户按条件快速找到约会方案。

功能：

- 筛选：预算、耗时、场景、兴趣标签。
- 灵感卡片列表。
- 推荐列表。
- 卡片详情可先用弹窗展示。

接口：

- `GET /api/v1/date-ideas`
- `GET /api/v1/date-ideas/recommend`

验收：

- 页面能展示后端内置约会灵感。
- 筛选条件变化后重新请求或前端过滤。
- 没有结果时展示温和空状态。

### 6.6 专属回忆

目标：记录重要瞬间，并支持图片上传。

功能：

- 回忆列表。
- 图片瀑布流或卡片流。
- 新增回忆。
- 上传图片。
- 可见性选择：仅自己 / 双方。
- 日期、地点、标签、正文。
- 默认以展示为主，点击右上角加号或“记录一段新的回忆”后展开新增表单。
- 上传图片后先展示本地预览，再保存回忆。

接口：

- `GET /api/v1/memories`
- `POST /api/v1/memories`
- `GET /api/v1/memories/{id}`
- `PUT /api/v1/memories/{id}`
- `DELETE /api/v1/memories/{id}`
- `POST /api/v1/files/images`
- `GET /uploads/images/{filename}`

验收：

- 能上传图片并获得 URL。
- 能创建带图片 URL 的回忆。
- 能查看回忆列表。
- 双方可见回忆在未配对时展示后端错误。

### 6.7 沟通建议 / AI

目标：用户表达困难时生成更温和的话术。

功能：

- 输入场景。
- 输入我的感受。
- 输入对方可能的感受。
- 输入沟通目标。
- 调用 AI 沟通建议。
- 展示建议、话术、风险等级、固定提醒。
- AI 未启用时展示可理解提示。

接口：

- `POST /api/v1/ai/communication-advice`

请求示例：

```json
{
  "scenario": "因为晚回消息吵架了",
  "myFeeling": "委屈、生气",
  "partnerFeeling": "可能觉得我管太多",
  "goal": "想好好表达，不想继续吵"
}
```

响应 `data` 示例：

```json
{
  "advice": "先表达自己的感受，再提出一个具体、可协商的请求。",
  "messageTemplate": "我感到有些委屈，是因为晚回消息让我担心。我希望下次很忙时可以简单说一声。",
  "riskLevel": "low",
  "reminder": "建议仅供参考，具体做法需要结合你们双方情况协商。"
}
```

验收：

- AI 默认关闭时，前端展示“AI 服务暂未启用”。
- AI 启用时，正常展示结构化结果。
- 不把用户输入默认保存到本地或后端。

### 6.8 我的 / 设置

目标：展示账号、配对状态和基础设置入口。

功能：

- 当前用户昵称。
- 头像占位。
- 伴侣信息。
- 菜单：个人资料、恋爱设置、隐私设置、数据统计、意见反馈、关于我们。
- 退出登录。

接口：

- `GET /api/v1/users/me`
- `GET /api/v1/pairings/me`
- `POST /api/v1/auth/logout`

验收：

- 能展示当前用户基础信息。
- 能退出登录并清除 token。

## 8. 前后端交互规范

### 8.1 统一响应

后端响应通常为：

```json
{
  "code": 200,
  "message": "成功",
  "data": {}
}
```

前端请求成功判断：

- HTTP 状态码为 2xx。
- `code === 200`。

业务失败：

- 展示 `message`。
- 不直接展示技术堆栈。

### 8.2 Token

登录成功后保存：

- `accessToken`
- `refreshToken`
- `tokenType`

请求头：

```text
Authorization: Bearer <accessToken>
```

MVP 可先把 token 存在 `localStorage`。后续如果做正式 App 或生产环境，需要重新评估更安全的存储方式。

### 8.3 错误处理

前端统一处理：

- 400：表单错误，提示用户修改输入。
- 401：登录失效，跳回登录页。
- 403：无权限，提示不可访问。
- 500：服务异常，提示稍后再试。
- 1801：AI 服务未启用。
- 1802：AI API Key 未配置。
- 1803：AI 服务调用失败。
- 1804：AI 响应格式异常。
